# 单图生成 Full State 22 桌宠

本文件面向执行生成任务的 AI。开始前先读取同目录的 `PET_MODEL_STANDARD.md`，最终只交付能够通过 `npm run verify:pet-package` 的自包含模型包。

## 输入与输出

最低输入是一张角色参考图。可选输入包括名称、性格、画风和禁止项。缺少名称时推断一个简短名称；不得因为缺少次要信息阻塞生成。

输出目录必须是：

```text
models/<pet-id>/
  pet.json
  spritesheet.webp
```

生成过程中的 prompts、逐帧 PNG、接触表和 QA JSON 放在工作目录，不要让运行时依赖它们。

## 生成流程

1. **建立身份基准**：从参考图提取稳定特征，包括头身比例、脸、眼睛、发型或轮廓、主辅色、材质、标记、服装和固有道具。不得在后续状态中新增、删除或换手道具。
2. **准备布局**：每个动作行是 8 个从左到右的独立姿势。生成时使用纯色、可确定性去除的色键背景；不得出现格线、标签、文字、场景、阴影、光晕或脱离身体的特效。
3. **生成基础状态**：先完成 `idle`、`running-right` 和 `running-left`，确认身份与移动朝向。只有当不对称标记和道具镜像后仍正确时，才可逐帧镜像得到左移动。
4. **生成任务状态**：分别生成 `waving`、`jumping`、`failed`、`waiting`、`running`、`review`。`running` 表示处理任务，不得画成脚步奔跑。
5. **生成方向状态**：先确定上下左右四个基准，再生成连续的 16 方向注视循环。普通角色不得靠旋转整张精灵伪造注视；眼睛、头颈、耳朵和上身按角色结构自然跟随。
6. **生成交互状态**：分别生成 `picked-up`、`dragging-left`、`dragging-right`、`drag-hold`、`falling`、`landing`。动作必须能按该顺序连续播放，不得把移动、下落和落地画成同一姿势。
7. **生成生活与情绪状态**：分别生成 `sleep`、`wake-up`、`happy`、`angry`、`sad`，保持同一角色身份和实际身体尺度。
8. **确定性处理**：从每个完整动作行恢复 8 个姿势，统一该行的实际角色尺度和锚点，输出 192×208 RGBA 单元格，再按固定行号组装为 1536×4576 图集。透明像素 RGB 清零。
9. **建立清单**：复制 `PET_MODEL_FULL_STATE_TEMPLATE.json` 为模型目录内的 `pet.json`，替换 ID、显示名、描述和必要的个性参数。不得改动状态 ID、行号和基础 adapter 绑定。
10. **验收**：生成接触表和动作预览，完成下面的 QA，运行严格包校验。失败时修复最小的完整状态行。

## 视觉硬门槛

- 同一角色的脸、比例、轮廓、颜色、材质、标记和道具在 176 帧内一致。
- 每个单元格非空，角色完整且不触边；相邻姿势不重叠、不跨槽。
- `idle` 有轻微但可见的呼吸或眨眼变化；循环首尾自然。
- 左右移动朝向正确且步态交替；不得用速度线、灰尘或地面阴影表达移动。
- 招手用肢体动作表达；跳跃用身体高度表达；不得使用浮动符号或动作线。
- `waiting`、`running` 和 `review` 在正常桌宠尺寸下能够明显区分。
- 拿起、拖拽、下落和落地构成连续的交互动作族。
- 开心、生气、难过三种情绪在正常尺寸下可识别，但不得改变角色身份。
- 方向基准必须明确：000 上、090 屏幕右、180 下、270 屏幕左；中间方向不得倒退或跳变。
- 不得有不透明色键、白底、棋盘格、文字、UI、裁切碎片、透明内部断层或隐藏 RGB 色边。

## 修复与重生边界

先判断失败属于结构还是视觉：

- 分格、裁切、基线、缩放、透明 RGB、固定背景属于确定性问题，必须确定性修复。
- 身份漂移、动作错误、缺少姿势、错误朝向、道具断裂或方向语义错误属于源视觉问题，重新生成该完整 8 帧状态行。
- 不得重新生成已经通过 QA 的状态行。
- 不得只重新生成一格并混入旧行；同一行必须来自一个连贯的动作家族。
- 同一根因连续失败两次后必须改变动作设计、布局或提取策略，不得无限改写相似 prompt。

## 最终交付

严格校验通过后，交付模型目录、`pet.json`、图集、接触表和校验 JSON。明确说明它使用 `workspace-launcher-pet/full-state-22@1`，可以在 LaunchPad 选择 `pet.json` 后直接导入，无需二次编码。
